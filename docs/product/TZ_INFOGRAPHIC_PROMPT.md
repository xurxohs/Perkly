# Промпт для инфографики по ТЗ Perkly

Сделай понятную продуктово-техническую инфографику по проекту Perkly. Цель инфографики: быстро показать, что уже реализовано в Perkly, на каком уровне, что не совпадает с ТЗ, чего нет и что нужно добавить.

Стиль: современная B2B/B2C SaaS-инфографика, чистый интерфейс, светлый фон, акцентные цвета Perkly: зеленый/лаймовый для готового, желтый для частично готового, красный/коралловый для отсутствующего, темный текст. Без перегруза. Инфографика должна быть понятной инвестору, продакту, разработчику и дизайнеру.

Формат: вертикальная инфографика 1080x1920 или один слайд 16:9. Используй карточки, иконки, прогресс-бары, таблицу статусов и дорожную карту.

## Заголовок

Perkly vs ТЗ: что уже есть, чего не хватает и что нужно реализовать

Подзаголовок:

Perkly уже сильнее обычного промокод-сервиса: есть marketplace, Telegram, escrow, бонусы, гео и seller dashboard. Главный gap по ТЗ — нужна отдельная B2B/B2C архитектура базы данных.

## Блок 1. Общая картина

Покажи две схемы рядом.

Слева: "Как устроено сейчас"

```text
User -> Offer -> Transaction
```

Подпись:

Текущая модель уже поддерживает пользователей, офферы, покупки, escrow, баллы, подарки и аналитику.

Справа: "Что требует ТЗ"

```text
users
profiles_b2c
companies_b2b
promocodes
promocode_activations
```

Подпись:

ТЗ требует отдельные сущности для B2C профиля, B2B компании, промокодов и истории активаций.

Главный вывод в центре:

Не переписывать Perkly с нуля. Нужно добавить недостающие B2B/B2C сущности поверх текущей сильной системы.

## Блок 2. Что уже есть и на каком уровне

Сделай таблицу или grid из карточек:

   Уровень: 90%

   Уровень: 65%
   Комментарий: есть `USER`, `VENDOR`, `ADMIN`, но ТЗ требует `B2C_USER`, `B2B_MERCHANT`.

4. B2C профиль
   Статус: сильный, но не полностью по ТЗ
   Уровень: 75%
   Комментарий: есть баланс, Perkly Points, покупки, подарки, подписки, Telegram binding. Не хватает отдельного `profiles_b2c`.

5. B2B / Seller dashboard
   Статус: частично готов
   Уровень: 60%
   Комментарий: есть dashboard, статистика, офферы, транзакции. Не хватает компании, ИНН и модерации.

6. Каталог и карточки
   Статус: сильный
   Уровень: 85%
   Комментарий: категории, поиск, flash drops, nearby, featured, stores, favorites.

7. Telegram
   Статус: очень сильный
   Уровень: 95%
   Комментарий: login, bot, referrals, gifts, nearby, notifications.

8. Геймификация
   Статус: выше уровня ТЗ
   Уровень: 90%
   Комментарий: Perkly Points, wheel, daily bonus, missions, squad rewards, tiers.

9. Marketplace core
   Статус: выше уровня ТЗ
   Уровень: 90%
   Комментарий: escrow, purchases, gifts, chats, disputes, reviews, Apple Wallet, Topka.

10. Analytics / CDP
    Статус: начальный уровень
    Уровень: 40%
    Комментарий: есть session id и события, но нет полного anonymous identity stitching.

11. QA/tests
    Статус: частично

## Блок 3. Что отсутствует по ТЗ

Сделай большой блок "Missing by ТЗ" с красными или коралловыми маркерами.

Отсутствует или почти отсутствует:

- `profiles_b2c` — отдельный B2C профиль пользователя.
- `companies_b2b` — отдельная B2B компания.
- `inn` — ИНН компании и проверка 9 цифр.
- Company moderation — статусы `PENDING_MODERATION`, `ACTIVE`, `SUSPENDED`.
- `promocodes` — отдельная сущность промокода.
- `promocode_activations` — история выдачи, показа, копирования и использования промокодов.
- `anonymous_id` — связка анонимного пользователя с реальным после логина.
- Refresh token — access token 15 минут + refresh token 30 дней.
- Server-side favorites — избранное должно храниться на backend.
- Server-side interests — интересы пользователя должны храниться на backend.
- Copy history — история копирования/активации кодов.
- B2B company application — заявка партнера.
- QA acceptance tests — тесты RBAC, INN, дат, скидок и миграций.

## Блок 4. Что есть, но надо привести к ТЗ

Сделай блок "Есть, но нужно довести".

1. `Offer` сейчас заменяет промокод.
   Нужно: либо добавить `Promocode`, либо расширить `Offer` полями `codeType`, `discountValue`, `validFrom`, `validTo`.

2. `Transaction` сейчас заменяет активацию.
   Нужно: добавить отдельный `PromocodeActivation` или `OfferActivation`.

3. `USER/VENDOR/ADMIN` сейчас заменяют роли ТЗ.
   Нужно: выбрать финальные роли и сделать маппинг с `B2C_USER/B2B_MERCHANT`.

4. `sessionId` сейчас заменяет anonymous identity.
   Нужно: добавить полноценную связку `anonymousId -> userId`.

5. iOS favorites сейчас локальные.
   Нужно: сделать server-side favorites для синхронизации iOS/web/Telegram.

## Блок 5. Что нужно реализовать

Сделай roadmap из 5 этапов.

### P0. Срочно

- Починить web seller dashboard API mismatch.
- Скрыть B2B кабинет от B2C пользователя.
- Зафиксировать ролевую модель.
- Добавить тесты `B2C -> B2B endpoint = 403`.

### P1. Архитектура БД

- Добавить `B2CProfile`.
- Добавить `Company`.
- Добавить `Promocode` или расширить `Offer`.
- Добавить `PromocodeActivation`.

- Добавить `SavedOffer`.

### P2. B2B кабинет

- Экран "Стать партнером".

- Поля: legal name, brand name, INN, phone.
- Проверка INN.
- Модерация компании.
- Создание промокода.
- Счетчик активаций.
- Дашборд промокодов.

### P3. B2C кабинет

- Серверное избранное.
- История кодов.
- "Мои интересы".
- "Мои купоны".
- "Сохраненные".
- "История активаций".
- Синхронизация iOS/web/Telegram.

### P4. CDP и персонализация

- `anonymousId`.
- Привязка анонимных событий к пользователю после логина.
- Рекомендации по интересам.
- Telegram-сегменты.
- Аналитика просмотров, копирований и покупок.
